# Native narrow integration decisions

The native adapter and request builder preserve the qualified prompts and schemas; application/domain/catalogue behavior is retained. `LLM_MODE=local` selects pinned native qwen3:8b, not the legacy OpenAI-compatible transport retained for offline regressions. Hosted configuration remains separate.

1. **Draft caps:** preserve the qualified extraction range ($0.01–$500) in unsigned local drafts, rather than silently clamping four amounts to the default $80/$80/$30/$30. `buildDraftPolicy` checks cent precision, category and limit relationships. Owner review/signing remains required. Quantity/cart maxima (5/10), 30-day expiry, refund rule, identity and provenance come from server defaults. The native manifest independently reconstructs these fields. Fixture and hosted cap behavior is retained.
2. **Deadlines/admission:** retain 55 seconds inference and the existing 60-second route/session/lease chain, including cleanup margin and absolute cancellation. Extraction bake-off median was 9.24 seconds. No inference occurs inside a SQLite transaction. One native inference is admitted per app process; additional overlapping requests fail closed with zero inference attempts. The runner is serial; exclusive runtime ownership is required. Multiple independent app processes must not share the runtime during qualification. No retry, repair or fallback.
3. **Fresh identity:** each call uses direct literal-loopback HTTP, GET version (0.40.15), GET tags, then one native chat. API digest is `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`; the different normalized on-disk hash is never accepted in its place. Tag metadata is a runtime assertion, not independent blob attestation. No pull/tag mutation is allowed during the owned run.
4. **UI:** four-limit/category extraction is disclosed before input. Defaults remain editable and visible in the field comparison; signing requires exact-term consent. Selection is five trusted aliases and exact quantity, then the unchanged mandate engine. Live local/configured model/digest and PayPal fixture/no-calls state are separate. Browser walkthrough evidence is recorded separately; source tests alone do not prove rendered usability.

## Strict native live contract

`test:ai-live` dispatches local mode to the versioned native-narrow runner. The old full-policy/hosted reconciliation is retained separately, including all earlier regressions. Native manifest: 20 explicit extraction sweeps (including intentionally ignored expiry/quantity/refund clauses), 20 exact SKU/quantity selections, five clean alias controls and all 45 corpus rows, three repetitions = 270 attempts. This is a small templated corpus, not unrestricted language validation.

Every successful row requires six exact capture events, three same-origin HTTP requests, one inference, runtime/digest checks, raw wire hash, full production-parser replay, request deep equality with the frozen narrow recipe, exact raw semantic output, rebuilt draft/cart/diff/provenance, deterministic engine verdict, one result, HTTP 200 and unchanged signed state. Missing/extra/duplicate rows fail. A wrong choice cannot pass through an engine refusal. All hostile rows require a successful exact clean pair with byte-identical chat request. Model refusal/prose/schema/timeout/identity failures fail. No PASS-bar reduction or unrecorded retry is permitted.

Hostile-description live cases use the existing app's merchant-text seam (`modelText`); that surface is deliberately ignored by the native request builder. The separate retained exclusion regression poisons actual imported catalogue display names/descriptions/imageAlt for all 45 corpus strings and proves identical request bytes. Both prove exclusion, not learned resistance. Owner-goal injection was not measured. Only M5 32 GB hardware was observed; model download 5.23 GB.

The strict typecheck's exact source-root manifest/count is extended from 71 to 76 for two production modules and three tests; checker logic, declaration patch, diagnostics policy and test assertions are retained. Passing still carries the existing `OVERLAY_ASSISTED_MODIFIED_DECLARATIONS` qualification; original pinned third-party declaration strictcheck is not claimed fixed.
